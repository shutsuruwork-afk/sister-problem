# お姉さん問題 ― 数学的アプローチのノート

対象は OEIS **A007764**：`(n+1)×(n+1)` の格子点グラフ上で、左上 `(0,0)` から
右下 `(n,n)` へ至る自己回避経路（同じ点を二度通らない経路）の総数 `a(n)`。
既知は `a(27)` まで（Jensen: 1–20、Iwashita: 21–22、Spaans: 23–25、Iwashita: 26–27）。
**`a(28)` が未解決の最前線**である。

このノートはそのうち「数学側」の担当分。実装の最適化は別セッション。

---

## 0. 検証基盤

まず信用できる土台を作った。独立な2実装が完全に一致している。

| 実装 | 手法 | 検証範囲 |
|---|---|---|
| `src/brute.c` | 素朴なDFS全列挙（DP機構に一切依存しない） | `n ≤ 6` |
| `src/frontier.py` | broken-profile フロンティアDP（Python、多倍長厳密） | `n ≤ 12` |
| `src/dp.c`, `src/dp2.c` | 同DP（C、法 `p` の剰余、開番地ハッシュ） | `n ≤ 17` |

- `n ≤ 6`：総当たり = フロンティアDP → `2, 12, 184, 8512, 1262816, 575780564`
- `n ≤ 12`：C版の剰余が Python 厳密値の剰余と全一致
- 得られた厳密値から成長定数を回帰すると **λ = 1.7444**。
  文献値（Bousquet-Mélou–Guttmann–Jensen）の **1.744550** と4桁一致する。
  外部データを一切参照せずに独立再現できている。

## 1. 主結果：フロンティア状態数の厳密な閉形式

フロンティアDPのメモリは「各層の到達可能状態数」で決まる。これが
**測定ではなく閉じた式で決まる**ことが分かった。

> **定理（実験的に n=2..16 で厳密検証）**
> 行走査 broken-profile DP において、行境界での到達可能状態数は
> ```
>   B(n) = Σ_{a+b=n} M_a · M_b = [x^n] M(x)^2 = M_{n+2} − M_{n+1}
> ```
> であり、行の途中でのピーク状態数はちょうどその2倍
> ```
>   peak(n) = 2 · ( M_{n+2} − M_{n+1} )
> ```
> ここで `M_k` は Motzkin 数、`M(x)` はその母関数。

`n = 2, …, 17` の実測値と**1つの不一致もなく**一致する（`src/state_count.py`）。
最大の検証点 `n=17` は `2(M_19 − M_18) = 23,325,804` で実測と完全一致。

### なぜこの形か（状態集合の特徴づけ）

行境界のプロファイルは `L = n+1` スロットの語で、記号は
`0`（プラグなし）/ `(` / `)`（弧の両端）/ `M`（始点 `(0,0)` を含む断片の自由端）。
`(`,`)` は対応付けが平面的なので括弧列として釣り合う。

**主張：`M` をまたぐ弧は存在し得ない。**
始点を含む経路断片は、処理済み領域（上から数行の長方形）の左上隅から
フロンティア上の1点まで走る曲線であり、この領域を2つに分断する。
弧はそのどちら側かに完全に含まれるしかないので、`M` の左右をまたげない。

したがって状態は `a + b = n` として
```
   (長さ a の Motzkin 語)  M  (長さ b の Motzkin 語)
```
と一意に分解され、個数は `Σ_a M_a M_{n−a}`。母関数関係 `M = 1 + xM + x²M²` から
`M² = (M − 1 − xM)/x²`、よって `[x^n]M² = M_{n+2} − M_{n+1}`。

逆にこの形の語はすべて実際に到達可能で、しかも数行進むだけで**飽和**する
（`n=14` では6行目以降ずっと `542895 = M_16 − M_15` で一定）。
`src/ranking.py` は「DPが到達する集合」と「上の語の集合」が
**集合として等しい**ことを `n ≤ 9` で確認している（個数一致だけではない）。

### 行途中の状態：なぜちょうど2倍か

頂点 `(i,j)` を処理した直後、その頂点が出した2本のプラグ
（下向き `D` = スロット `j`、右向き `R` = スロット `j+1`）は
頂点の次数が0か2（端点なら1）であることから
```
   (0,0)   (x,0)   (0,x)   ( ( , ) ) …隣接した対応括弧
```
の4形しか取り得ない（実測でも確認：両方非空なのは常に隣接対応括弧のみ）。
この2スロットを**1スロットに縮約**する（`x` は残す、`(0,0)` と対応括弧対は
ともに `0` にする）と、長さ `n+1` の妥当語 `u` に戻る。1ビット `b` で
`(x,0)` と `(0,x)`、`(0,0)` と対応括弧対を区別すれば
```
   index = 2 · rank(u) + b
```
が `[0, 2·B(n))` への全単射になる。縮約後に `u[j] = 0` となる語は
`B(n−1)` 個なので、状態数は
`B(n−1) + 2(B(n) − B(n−1)) + B(n−1) = 2·B(n)`。
**実測の「ちょうど2倍」がこれで説明される。**

### 系：必要メモリが厳密に分かる

1状態あたり8バイト（後述の剰余1個）とすると：

| n | 行境界 状態数 | 行途中ピーク | 行境界 | ピーク |
|---:|---:|---:|---:|---:|
| 20 | 258,215,664 | 516,431,328 | 1.9 GB | 3.8 GB |
| 24 | 16,626,415,975 | 33,252,831,950 | 124 GB | 248 GB |
| 26 | 135,015,505,407 | 270,031,010,814 | 1.0 TB | 2.0 TB |
| **27** | **385,719,506,620** | **771,439,013,240** | **2.9 TB** | **5.7 TB** |
| **28** | **1,103,642,686,382** | **2,207,285,372,764** | **8.2 TB** | **16.4 TB** |
| 29 | 3,162,376,205,180 | 6,324,752,410,360 | 23.6 TB | 47.1 TB |

`n → n+1` で状態数はほぼ3倍（Motzkin の成長率）。
**26 → 28 は状態数で約8.2倍**、これが未解決たるゆえんである。

## 2. 密配列化：ハッシュ表を捨てる

上の分解はそのまま**全単射な順位付け（ranking）**を与える：

```
rank(w) = Σ_{a'<a} M_{a'}·M_{n−a'}  +  rankM(左語)·M_b  +  rankM(右語)
```

`rankM` は Motzkin 語の標準的なバロット経路順位付け（`src/ranking.py`）。
これは `[0, M_{n+2} − M_{n+1})` への全単射であることを `n ≤ 10` で
往復検証済み。

意味するところ：**DPの各層は「順位で添字づけられた密な剰余配列」でよい**。
鍵の格納もハッシュの空きスロットも不要。

| 格納方式 | 1状態あたり |
|---|---:|
| 多倍長 + ハッシュ表（負荷率0.6、鍵8B） | 約 147 B |
| 剰余 + ハッシュ表（負荷率0.6、鍵8B） | 約 27 B |
| **剰余 + 順位付き密配列** | **8 B** |

素朴実装比で **約18倍**のメモリ削減。

### 実証

`src/dense.py` はこの密配列だけでDPを回す参照実装。ハッシュ表も鍵も使わない。

```
 n   a(n)                              一致   配列長 = 2B(n)   実際に使われた要素数
 6   575780564                         OK              392            392
 8   3266598486981642                  OK             2706           2706
10   1568758030464750013214100         OK            19426          19426
```

`n = 2..10` で既知値を厳密に再現し、かつ **配列の使用率は 100%**
（`max live == 配列長`）。添字付けに1要素の無駄も無いことの実証である。

なお `rank` / `unrank` は1状態あたり `O(n)` かかるので、素の実装だと
ハッシュ版より遅くなる。実用にはランク順に走査して入力側の `unrank` を
オドメータで償却する（`O(1)`）のが定石で、そこは実装側の仕事。

## 3. 剰余 + CRT

`a(n)` 自体が巨大なので、値の格納幅が効く。回帰から
```
   a(26) ≈ 163 桁 (542 bit),  a(27) ≈ 176 桁 (585 bit),  a(28) ≈ 189 桁 (629 bit)
```
（文献の λ から独立に出る 189.5 桁とも一致）。

62ビット素数なら **12個**で余裕をもって復元できる。各素数の走査は
完全に独立なので、**12台に並列化してもメモリは1台分**。
多倍長をそのまま持つと1状態80バイト → 176 TB に対し、
剰余なら8バイト → 17.7 TB。**メモリ10倍、計算量12倍**の交換であり、
このメモリ律速の問題では明確に得。

## 4. 効かなかったアプローチ（負の結果）

やってみて駄目だったものも記録しておく。ここが一番時間を節約する。

### 4.1 両側枝刈り（到達可能 ∩ 逆到達可能）は無意味
「前から到達できるが後ろから完成できない」状態を捨てれば減るはず、と思ったが、
実測すると有用状態の割合は `n` とともに **1に近づく**（`src/useful.py`）：

| n | 6 | 8 | 10 | 11 |
|---|---|---|---|---|
| 有用/到達 | 0.9235 | 0.9276 | 0.9304 | **0.9314** |

節約は7%未満、しかも減っていく。**この状態空間は本質的に既約**。

### 4.2 180°回転による meet-in-the-middle は成立しない
格子と2端点は `ρ(i,j) = (n−i, n−j)` で不変で、行優先順序はちょうど反転する。
プロファイルのスロット `m` は `n+1−m` に写り、`ρ*` は
「語の反転 + `(`↔`)` 交換」という安価な対合になる。ここまでは正しい。

しかし `a(n) = Σ_σ F(σ)·B(σ)` の `B` は「状態 `σ` の**完成数**」であって、
後半DPの値そのものではない。両者は Temperley–Lieb の
グラム行列（メアンダー行列）`M` を挟んで `B = M·F∘ρ*` と結ばれる。
`M` の適用コストが層サイズを超えるため、**時間が半分になるという話にはならない**。
`ρ*` は検証用の不変量としては使える。

### 4.3 連結性を局所化する試み（Euler標数）は原理的に不可能
経路は「セルの2彩色の界面」と1対1対応する（内点で市松模様を禁じれば
次数は0か2、隅2点だけ次数1）。残る条件は「閉路が無い＝両色クラスが連結」。
これを局所量で書けないか試したが：

- `V − E = 1` は閉路数 `k` によらず恒等的に成り立つ（各閉路の寄与が0）。
- 色クラスの Euler 標数の和も `χ_0 + χ_1 = 2` で定数。

**Euler標数は連結性を見ない。** これが「彩色だけなら `2^n` 状態で済むのに
経路数え上げは `3^n` かかる」ことの理由であり、局所トリックが無いことの説明でもある。

### 4.4 反対角走査（転置対称性を使う案）は逆効果
主対角に関する転置 `τ` は問題の対称性なので、反対角走査なら
処理済み領域が `τ` 不変になり `F(σ) = F(rev σ)` で半減する……
と考えたが、反対角のカットを横切る辺は約 `2n` 本（行カットは `n+1` 本）で、
状態空間が `3^n → 3^{2n}` に悪化する。**行走査が最小カットであり最適**。

## 5. `a(28)` に何が要るか（定量）

素数1個あたり：

| 項目 | 値 |
|---|---|
| ピーク状態数 | 2.207 × 10¹² |
| 層1枚（8B/状態） | 16.4 TB |
| ping-pong 2枚 | 32.8 TB |
| 総遷移回数 | ≈ 3.3 × 10¹⁵ |
| 計算時間（10⁸ 遷移/秒/コア） | ≈ 9,200 コア時 |

12素数で **約11万コア時 ≒ 12.6 コア年**。1000コアなら約5日。
**計算量は問題ではない。壁はメモリの 16〜33 TB。**

### 突破口の候補

1. **外部記憶DP**：層遷移はソート＋マージのストリーム処理にできる。
   16 TB の NVMe は現実的な価格。I/O が支配的になるので、
   語の先頭 `t` スロットで約 `3^t` 分割して部分ごとに処理するのが素直。
2. **マーク位置によるブロック分解**：状態は `⊔_a (S_a × S_b)` に分解され、
   `n=28` の最大ブロックは `M_0·M_28 = 2.08×10¹¹`（1.66 TB）。
   全体の 1/10 まで落ちる。ただし合流遷移でマークが遠くへ飛ぶため、
   ブロック間結合の扱いが要検討。
3. **複数素数の同時走査**：1状態に4剰余（32B）を持たせれば
   走査コストは1/4。メモリと時間の交換パラメータになる。

いずれも「数学的に状態数を減らす」話ではなく、
**確定した 1.1×10¹² 個の状態をどう置くか**という工学の話になる。
§4 の負の結果が示す通り、状態数そのものはこの定式化では削れない。
